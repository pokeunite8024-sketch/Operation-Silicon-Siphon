# Challenge Questions & Investigation Checklist

Complete each of the 6 investigation stages below. You can verify your answers interactively by running:
```bash
python verify_flag.py
```

### Question 1: Initial Infiltration Vector
* **Category:** Endpoint / Authentication Forensics
* **Artifact:** `evidence/endpoint/var_log/auth.log`
* **Prompt:**  
  The adversary gained interactive access to workstation `aegis-eng-ws01` via SSH. Before successfully logging into engineer Marcus Chen's account (`eng_mchen`), the attacker attempted brute-force logins with default accounts.  
  **What is the IP address of the internal compromised device used to conduct this SSH attack?**
* **Hint:** Look for `Failed password` and `Accepted password` entries in `auth.log`. Note the originating IP address.

---

### Question 2: Privilege Escalation
* **Category:** Linux Host Forensics / GTFOBins
* **Artifact:** `evidence/endpoint/var_log/auth.log` and `evidence/endpoint/home/eng_mchen/.bash_history`
* **Prompt:**  
  Immediately upon authenticating as `eng_mchen`, the attacker executed a command with elevated privileges using `sudo` without being prompted for a password.  
  **Which system binary was executed via sudo to spawn a root shell?** (e.g. `/usr/bin/...` or binary name)
* **Hint:** Inspect the `COMMAND=` field logged by `sudo` in `auth.log`.

---

### Question 3: Physical Device Forensics (USB Artifacts)
* **Category:** Hardware / Kernel Forensics
* **Artifact:** `evidence/endpoint/var_log/syslog`
* **Prompt:**  
  Kernel log records reveal that a physical USB storage drive was plugged into the workstation during the intrusion window to stage exfiltration tools.  
  **What is the 20-character Serial Number of the inserted USB flash drive?**
* **Hint:** Filter `syslog` for `SerialNumber:` or `usb 1-2:` messages generated by the Linux kernel `xhci_hcd` driver.

---

### Question 4: Hardware Signal Analysis (SPI Bus Forensics)
* **Category:** Hardware Forensics / Signal Processing
* **Artifact:** `evidence/hardware/spi_boot_capture.vcd`
* **Prompt:**  
  During bootloader execution on the hardware testbench, an attached logic analyzer captured an SPI flash read transaction (`spi_cs_n`, `spi_clk`, `spi_mosi`, `spi_miso`). The microcontroller read 32 bytes of secure one-time-programmable (OTP) hardware key material starting at memory address `0x001000`.  
  **What is the 32-character hardware OTP secret key decoded from the SPI MISO data stream?**
* **Hint:** Open the VCD file in **PulseView / Sigrok** with the SPI protocol decoder (Mode 0: CPOL=0, CPHA=0, sample on rising edge of `spi_clk` when `spi_cs_n` is LOW), or write a small Python clock-edge state machine parser.

---

### Question 5: Covert ICMP Carving & AES Key Derivation
* **Category:** Network Forensics & Cryptography
* **Artifacts:** `evidence/network/lab_traffic.pcap`, plus outputs from Q3 and Q4
* **Prompt:**  
  The attacker exfiltrated a staging manifest across an encrypted ICMP covert channel directed toward `198.51.100.77`.  
  - Carve the ICMP Echo Request payloads (Identifier `0x1337`, sequential ordering).
  - The exfiltrated stream was encrypted using **AES-256-CBC**:
    - **AES Key (32 bytes):** `SHA-256` hash of the SPI OTP secret recovered in Question 4.
    - **AES IV (16 bytes):** `MD5` hash of the USB Serial Number recovered in Question 3.
  - Decrypt the ciphertext to recover the JSON exfiltration manifest.  
  **What is the staging passkey (`staging_key`) recovered from the decrypted manifest?**
* **Hint:** In Wireshark, use filter `icmp && ip.dst == 198.51.100.77`. Extract the data payloads in sequence order 1..4 (32 bytes each = 128 bytes total). Decrypt using CyberChef or Python (`cryptography`).

---

### Question 6: Staging De-obfuscation & Flag Recovery
* **Category:** Binary Analysis / Data Recovery / File Carving
* **Artifacts:** `evidence/staging/staged_telemetry.bin`, plus output from Q5
* **Prompt:**  
  The adversary prepared a compressed staging container in `/var/tmp/` containing the stolen hardware IP files. To defeat automated DLP pattern matching:
  1. The adversary applied a byte-wise XOR mask of `0x5A` to the first 64 bytes.
  2. The first 4 magic bytes were corrupted to `0xDE 0xAD 0xBE 0xEF`.
  - Apply XOR `0x5A` to the first 64 bytes.
  - Restore the standard ZIP header magic bytes (`PK\x03\x04` / `0x50 0x4B 0x03 0x04`).
  - Extract the password-protected ZIP archive using the passkey recovered in Question 5.
  - Read `flag.txt`.  
  **What is the final capture flag?**
* **Hint:** A 10-line Python script or hex editor (VS Code Hex Editor / CyberChef) can easily invert the XOR mask, patch the 4 magic bytes, and extract the ZIP.
