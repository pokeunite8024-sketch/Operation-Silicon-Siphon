# Challenge Questions & Investigation Checklist

Complete each of the 6 investigation stages below. You can verify your answers interactively by running:
```bash
python verify_flag.py
```

---

### Question 1: Initial Infiltration Vector
* **Category:** Endpoint / Authentication Forensics
* **Artifact:** `evidence/endpoint/var_log/auth.log`
* **Prompt:**  
  The adversary gained interactive access to workstation `aegis-eng-ws01` via SSH. Before successfully logging into engineer Marcus Chen's account (`eng_mchen`), the attacker attempted multiple brute-force logins.  
  **What is the IP address of the internal compromised device used to conduct this SSH attack?**
* **Hint:** Look for `Failed password` and `Accepted password` entries in `auth.log`. Note the originating IP.

---

### Question 2: Privilege Escalation
* **Category:** Linux Host Forensics / GTFOBins
* **Artifact:** `evidence/endpoint/var_log/auth.log` and `evidence/endpoint/home/eng_mchen/.bash_history`
* **Prompt:**  
  Immediately upon authenticating as `eng_mchen`, the attacker executed a command with elevated privileges using `sudo` without being prompted for a password.  
  **Which system binary was executed via sudo to spawn a root shell?** (e.g. `/usr/bin/...` or binary name)
* **Hint:** Inspect the `COMMAND=` field logged by `sudo` in `auth.log`.

---

### Question 3: Physical Device Forensics (USB Artifacts)
* **Category:** Hardware / Kernel Forensics
* **Artifact:** `evidence/endpoint/var_log/syslog`
* **Prompt:**  
  Kernel log records reveal that a physical USB storage drive was plugged into the workstation during the intrusion window to stage exfiltration tools.  
  **What is the 20-character Serial Number of the inserted USB flash drive?**
* **Hint:** Filter `syslog` for `SerialNumber:` or `usb 1-2:` messages generated by the Linux kernel `xhci_hcd` driver.

---

### Question 4: Disguised Persistence
* **Category:** Persistence Hunting
* **Artifact:** `evidence/endpoint/etc/cron.d/.ntp-sync` and `evidence/endpoint/usr_local_bin/.sys_health.sh`
* **Prompt:**  
  To maintain root access even across system reboots, the adversary scheduled a periodic task masquerading as a routine system service.  
  **What is the absolute filesystem path of the malicious cron configuration file created by the attacker?**
* **Hint:** Examine the hidden configuration file located in the system-wide cron directory.

---

### Question 5: Covert C2 & DNS Exfiltration
* **Category:** Network Forensics / Protocol Analysis
* **Artifact:** `evidence/network/lab_traffic.pcap`
* **Prompt:**  
  The adversary did not use regular HTTP/HTTPS to communicate with their Command & Control (C2) server; instead, they established a covert channel using DNS tunneling.  
  1. **What is the Fully Qualified Domain Name (FQDN) of the attacker's C2 server?** (Question 5a)
  2. **Reassemble the sequential hex payloads transmitted across the DNS queries to reconstruct the ASCII decryption key.** (Question 5b)
* **Hint:** Open `lab_traffic.pcap` in Wireshark or use `tshark` / Python. Filter for DNS queries (`dns.flags.response == 0`) and look for anomalous subdomains with `seq01`, `seq02`, etc. Reconstruct the full hex string and convert to ASCII.

---

### Question 6: File Carving, Header Repair & Final Flag
* **Category:** Binary Analysis / Data Recovery / Cryptography
* **Artifact:** `evidence/staging/staged_telemetry.bin`
* **Prompt:**  
  The adversary prepared a compressed staging container in `/var/tmp/` containing the stolen hardware IP files. To prevent corporate Data Loss Prevention (DLP) engines from detecting a standard archive file format, the adversary scrambled the first 4 magic bytes of the file.  
  1. Inspect `staged_telemetry.bin` in a hex editor or Python. Identify the corrupted magic bytes.
  2. Restore the original standard ZIP magic bytes (`PK\x03\x04` / `0x50 0x4B 0x03 0x04`).
  3. Extract the password-protected archive using the secret key recovered from Question 5.
  4. Read `flag.txt`.  
  **What is the final capture flag?**
* **Hint:** Standard ZIP archives begin with hex `50 4B 03 04`. Once the header is corrected, extract with standard zip tools (`unzip`, 7-Zip, or Python's `zipfile`) supplying the DNS decryption password.
